# Codex Remote 0.3.1 流式响应修复

## 改动

长会话原来每个桌面 patch 都投影并重传完整历史，手机反复解析并渲染整段 Markdown，网络慢时积压的中间状态仍排队显示。此次改为：

- 桌面 patch 仍逐条合并，普通投影每 150ms 合并一次；完成、失败、中断和审批变化优先发送。
- Bridge 首次发送完整快照，随后发送带 baseRevision 的变更项与元数据；拥塞时保留最新状态。
- 中转只推送手机当前选中的聊天，为各连接维护增量基线；缺口请求重建快照，旧客户端仍兼容完整快照。
- 手机校验版本后合并变更，保留未变消息对象、缓存行渲染，普通刷新合并 60ms；完成状态直接刷新。
- 聊天列表、读取及文件查询不再写入副作用命令日志；写操作仍保留去重与结果未知保护。
- 电脑控制接口保留手机刷新确认时间。统计使用同一电脑时钟计算往返耗时，不用手机时钟推断单向延迟。
- 修复 watcher 继承旧桌面 app-tools 管道后历史聊天加载失败：仅在请求发出前连接返回 ENOENT 时发现当前管道，避免重复执行工具请求。

## 实际验收（2026-11-06，北京时间）

最终安装包 com.remoteapp.mobile / 0.3.1 / code6，x86_64 API35 模拟器，经已部署国内 WSS 中转连接当前桌面运行时。

1. 从 App 已有聊天列表打开专用测试聊天；此前该聊天无 desktop owner，重新加载后显示历史且连接错误消失。
2. 在 App 输入并发送连续 80 行输出测试，正文最终包含 STREAM_031_FINAL_OK。独立桌面 IPC 订阅确认同一 threadId 01a1abe9-85da-7751-99d3-9c1aae69f3b8、最终全文与完成状态；Android 实际界面显示最终标记、复制操作和发送按钮。
3. 桌面完成到电脑收到手机双帧刷新确认 727ms；147 个刷新确认往返耗时中位数 260ms、最大 1249ms。确认含完整公网往返与手机调度，因此不是严格的单向显示延迟测量，也不保证所有网络均小于一秒。手机时钟有偏移，不采用跨设备时钟相减的负值。
4. 本会话历史快照 1,244,784 字节，Android 实际打开并显示本轮最新进度。12 秒取样只有 2 次投影、3 次刷新确认，样本不足以宣称长会话 P95 或整轮完成延迟；本会话仍运行，没有冒充已完成的长会话结束测试。
5. 模拟器飞行模式后出现离线/缓存提示，恢复网络、后台返回前台后连接恢复，仍为同一聊天；本次没有发送离线写命令，未把它作为重复执行验收。

专用输出测试的同源投影估算：165 帧，若每帧完整快照为 1,311,623 字节，实际增量序列（含初始基线）为 560,541 字节。此数字是订阅数据序列的序列化估算，不是公网抓包；合成超过 1MB 历史的回归测试确认单条变更小于 1KB。

24 项自动测试、根与手机 TypeScript 检查通过；production 构建及签名检查通过。自动测试覆盖增量顺序/删除、完成清除 activeTurnId、版本缺口、拥塞最新状态、连接重置基线、聊天路由和旧客户端最终状态。
