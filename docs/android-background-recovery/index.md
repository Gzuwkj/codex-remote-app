# Android 后台通知恢复（0.5.3）

## 诊断

用户真机为华为、兼容 Android，具体型号与系统版本未知。云日志中，真机前台与原生通知连接在同一时刻关闭，重新打开 App 后同时认证。服务端无法判断是华为后台管理、进程回收还是网络限制；不能宣称已确定真机系统根因。

旧版 0.5.2 在现有 Android 模拟器进入强制 Doze 后也成功收到真实测试完成事件。因此旧版问题并未在标准 Android 上复现，不能把华为现象直接等同于 Doze。

代码确认一个独立恢复缺陷：重连定时器与服务启动可并发创建通知连接，旧连接失败/关闭回调没有完整的代际校验。云日志曾显示真机重复通知连接。

## 实现

- 原生服务的连接、认证、失败、关闭与重试统一在主线程处理，按 generation 和 socket identity 检查归属；重连前取消旧连接、认证超时和重试任务。旧连接的 4003 回调不再关闭新服务。
- 增加 15 秒认证超时，系统默认网络变化后重新认证、按已有事件游标补发；退出休眠、亮屏/解锁时重新检查连接。
- 连接页面显示服务是否运行、是否在线、系统电池优化豁免及系统后台限制状态，不再仅显示“已开启”。页面打开期间更新状态。
- 提供“后台运行与电池设置”，由用户通过系统页面授权忽略电池优化；没有自动点击真机设置，不添加永久唤醒锁。
- 保留原生 remoteMessaging 前台服务、常驻通知、断线补发和点击打开同一聊天；新增网络与电源恢复日志。

## 实际验收

在现有 emulator-5570 生产包 com.remoteapp.mobile 中安装最终 0.5.3/code11：

- 从 App 连接信息进入后台运行设置，系统展示后台常驻授权说明；点击 Allow 后返回，App 显示已允许后台运行。
- 退到 Android 桌面，强制 deviceidle=IDLE；从桌面专用 QA 聊天发起安全任务。原生日志记录 foreground=false 的 cursor=16 完成事件，系统通知栏展示“任务已完成”。点击真实通知，打开 QA 同一聊天并显示 BACKGROUND_NOTIFICATION_053_OK。退出强制 Doze 并恢复原电源状态。
- App 保持后台，关闭模拟器 Wi-Fi，确认默认网络 none；恢复 Wi-Fi 后，原生网络回调重新认证，未打开 App 即恢复 online=true。以本次 relay.start 为边界核对日志，模拟器当前通知连接为 1 条。
- 最终生产构建和签名校验通过。真实华为设备不在 adb 列表中，无法操作或读取本机日志；模拟器结果不能替代华为真机验证。

## 华为设备设置

安装新版后，在 App“聊天连接信息/选择计算机 → 后台运行与电池设置”允许系统授权。随后在华为设置中搜索“应用启动管理”，关闭 Codex Remote 的自动管理，允许自启动、关联启动和后台活动；近期任务中锁定 App。具体入口随系统版本不同。

这类系统授权需要用户在真机上执行。后台长连接会增加耗电。被系统强行停止或厂商清理后，不能保证依靠应用自身实时通知；当前没有接入华为/HMS、其他厂商或 FCM 系统推送，需相应应用注册及开发者配置，不能宣称已具备厂商推送送达保证。
